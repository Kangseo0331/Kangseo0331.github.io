\## \\[BOF\]



\## 메모리 오염 공격 (Memory Corruption)



프로그램의 메모리 공간에 허용된 용량보다 많은 데이터를 주입하여 인접한 메모리 영역의 데이터를 덮어쓰거나 손상시키는 공격



\-   Buffe Overflow  

\    할당된 버퍼의 범위를 넘어 데이터를 덮어씀

\-   Use-After-Free  

\    해제된 메모리 영역을 다시 사용 → heap에서 발생

\-   Null Pointer Dereference  

\    널포인터 역참조

\-   Double free  

\    이미 해제된 메모리를 다시 해제

\-   Out-of-Bounds Write  

\    허용된 메모리 범위 밖에 데이터를 씀



\## Buffer OverFlow (BOF)



할당된 버퍼의 크기보다 더 많은 데이터 입력 → 인접한 메모리 영역까지 덮어쓰는 취약점



\-   Stack BOF

\-   Heap BOF



\#### \*buffer



임시 저장 공간, 여러 바이트를 담는 배열(공간)



\-   특별한 종류의 변수가X

\-   크기가 잇고 경계 체크가 없는 배열

\-   \*\*배열\*\* → 인덱스 순으로 저장 : \*\*낮은 주소 → 높은 주소\*\* 순 저장

\-   char 동적할당\* → 할당된 chunk 안에서 낮은 주소 → 높은 주소 순 저장

\-   \*\*구조체 안의 배열\*\* → 바로 뒤(높은 주소 쪽) 변수 덮어씀



\#### \*alignment 정렬



\-   CPU가 메모리에 접근할 때 4바이트(또는 특정 배수) 단위로 정렬된 주소에 접근하는 것이 빠르고 효율적

\-   지역변수 전체 공간을 할당할 때는 4의 배수로 반올림해서 잡음

\-   공간 안에서 각 변수는 실제 타입 크기만큼 메모리 사용



\#### 예시



\`\``

void vuln(){

	char buf\[12];

	printf("input: ");

	gets(buf);

}



int main(){

	vuln();

	puts("done");

	return 0;

}

\`\``



\-   gets() 입력 길이에 제한X

\-   buf는 12바이트지만 gets() 사용으로 더 입력 가능

\-   segmentation fault : 프로그램이 접근 권한이 없는 메모리 영역을 읽거나 쓰려고 할 때 발생하는 오류



\#### Ret Overwrite



함수가 종료된 후 돌아갈 위치를 저장하는 Return Address를 공격자가 원하는 값으로 덮어쓰는 공격 기법

\-   함수 호출  

\    → 프롤로그 : return addr & 지역변수 push  

\    → 배열 저장 과정에서 return addr 침범

\-   ret 실행 → 원하는 값이 들어있는 return addr을 EIP에 저장

\## Shellcode Ijection



스택에 명령어를 적어두고 반환 주소 조작하기



\#### ret overwrite 이용하기



\-   우리가 정할 수 있는 것

\-   스택 버퍼에 쓰는 값

\-   Ret Overwrite로 EIP에 먹이는 값

\-   스택 버퍼 ← 원하는 명령어 넣어두기

\-   EIP ← 원하는 명령어가 있는 주소



\#### Shellcode



프로그램의 취약점을 이용해 공격자가 원하는 동작을 수행하도록 만든 기계어 코드



\-   원래 shell을 위한 코드였기 때문에 붙은 이름

\-   파일 읽기, 시스템 콜 호출 등 다양한 동작을 수행하는 코드라는 의미도 있음

\-   CPU가 읽을 메모리에는 기계어가 있음 → 기계어 넣어줘야 함



\#### Shellcode Injection



버퍼에 Shellcode 넣어두고 반환주소가 스택의 Shellcode로 가게 하는 공격



return addr : buf 주소



\| return addr : buf 주소 |   |

\| --- | --- |

\| saved ebp : AAAA | ← ebp |

\|    shellcode      \\_\\_\\_\\_\\_\\_\\_\\_\\_\\_\\_\\_\\_\\_\\_\\_      nop pad ​       |                   ← buf 주소 |

\| eax | ← esp |



\-   스택에 shellcode 주입

\-   반환주소를 스택 주소로 덮기

\-   nop pad (0x90)

\-   공격자는 쉘코드가 메모리의 어디에 위치하는지 알기 어렵다

\-   return addr 을 덮어쓸 때 쉘코드의 정확한 시작 주소를 지정하는 대신 nop 영역 가리키도록 지정

\-   nop sled : 연속해서 nop 실행하다가 shellcode에 도착할 수 있음



\### 여러 바이트 값 저장



\-   Big-endian : 상위 바이트부터 낮은 주소로 배치

\-   Little-endian : 하위 바이트부터 낮은 주소로 배치 ← x86

→ 주소를 넣고 싶다면 바이트 단위(16진수 2개)에서 뒤집어서 넣어야 함

\## NX



\#### sellcode Injection이 가능했던 이유



\-   스택이 가진 권한

\-   버퍼에 임의의 값 쓰기 (w)

\-   CPU가 스택에 있는 명령어 실행 (x)

\-   버퍼에 쓴 값을 → 실행할 수 있었기 때문에 BOF 취약점 발생



⇒ 둘 중 하나 차단하면 막을 수 있음



: 한 메모리 구간에 쓰기와 실행가



\#### W⊕X 정책



한 메모리 구간에 쓰기와 실행 둘 중 하나만 두는 정책



\#### NX bit



W⊕X 정책을 적용한 프로세서 기능



관련 옵션 : -z execstack (NX 끄기)



\## 코드 재사용 공격



\-   NX bit 가 막은 것 : 공격자가 직접 실행 가능한 영역에 명령어를 쓰는 것

\-   명령어를 썼다면 → 실행불가 (w만 사용)

\-   실행하려면 → 명령어를 쓸 수 없음 (x만 사용)

\-   NX bit 우회 : 기존의 명령어를 사용하기 (x만 사용)

\-   이미 존재하는 라이브러리 함수

\-   기존 코드의 작은 조각들



\#### ret2win



바이너리에 있지만 실행되지 않는 함수 → 목표함수



목표함수의 주소를 구해 → 취약 함수의 스택 프레임 return addr을 덮으면 → EIP에 목표함수 주소 저장 가능

\-   <+3> EBX 레지스터의 값 저장 → 일반적인 프롤로그와 달리 EBX로 argv를 받음

\-   프롤로그부터 버퍼 생성 이전까지 명령어들 → 함수 호출 준비, 지역변수 공간 확보, 주소 계산  

\    → ebp의 기준점을 바꾸지는 않음

\-   <+39> - <+43> : 버퍼 생성 → push(매개변수로 입력) → gets 호출

\-   argv (Argument Vector) : 명령줄 인자의 배열 → argv value : func의 인자로 들어가는 매개변수 value

\-   0x1c = 16+12 = 28
