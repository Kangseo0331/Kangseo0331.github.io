## 시스템 해킹

프로그램이나 시스템의 취약점을 분서가고, 이를 이용해 권한을 상승시키거나 임의의 코드를 실행하는 일련의 과정

→ pwnable은 시스템 해킴의 일종

## 포너블

* CTF의 문제 유형
* 시스템 해킹의 한 갈래
* 프로그램의 메모리 취약점을 이용해 시스템을 장악하거나 동작을 조작하는 기술
* 주로 운영체제나 프로그램 보안 취약점 분석, 공격

  * 관리자 권한 획득
  * 프로그램 흐름을 해커가 원하는 방식으로 바꾸기

## 1. 메모리 구조

```
소스코드  —[컴파일러]—>  오브젝트 파일(.o)  —[링커]—>  ELF 실행파일  —[로더]—>  프로세스
																								실행전       실행     메모리 적재
```

* 소스코드 : 작성한 코드 파일 → meow.c
* 프로그램 : 빌드한 실행파일 → gcc -o meow meow.c 로 컴파일 후 생성된 실행 파일 meow
* 프로세스 : 프로그램 실행한 것 → meow 실행하는 순간 프로세스 생성
* \*compile = 소스코드 → 오브젝트 파일\
  *build = compile + linking 등 실행파일 만드느 전체 과정

## 메모리 4영역

* **코드**       실행 코드가 들어있는 공간
* **데이터**   초기화된 데이터가 저장되는 공간
* **힙**          프로그램 실행 중 동적으로 사용되는 공간 (낮은 주소(아래) → 높은 주소(위))
* **스택**       함수 호출 시 인자, 지역 변수, 리턴 주소 등이 저장되는 공간 (높은 주소(위) → 낮은 주소(아래))

#### 코드 Code

시스템이 알아들을 수 있는 실행 명령어(기계어)가 저장되어 있음

* 코드 세그먼트 Code Segment / 텍스트 세그먼트 Text Segment
* 컴파일된 함수 코드, 제어흐름 관련 명령어 등
* x, r 권한만 부여

#### 데이터 Data

프로그램 시 사용되는 데이터 저장

* 전역변수 global variable, 정적변수 static variable 들어감
* 세분화한 주소

  * 데이터 세그먼트 (.data) 초기화O, 전역변수, 정적 변수
  * BSS 세그먼트 (.bss) 초기화X, 전역변수, 정적변수
  * 리소스 데이터 세그먼트 (.rodata) 초기화O, 읽기 전용(read only data), 주로 상수

#### 힙 Heap

프로그램이 실행 중에 동적으로 사용되는 영역

* 하위 메모리 주소 → 상위 메모리 주소 확장
* malloc, calloc, new → 실행 중 동적으로 할당
* free(), delete() → 개발자가 직접 해제
* 메모리 해제하지 않고 반복적인 메모리 할당 누적 → 메모리 누수 memory leak 발생

#### 스택 Stack

프로그램 로직이 동작하기 위한 인자, 프로세스 상태 저장

* 함수 호출 → 지역변수, 매개변수, 반환 주소 저장
* 상위 메모리 주소 → 하위 메모리 주소 확장

## 2. 레지스터

CPU 내부 연산용 임시 저장소

* CPU 연산, 어셈블리어 동작에 사용
* 각 레지스터는 특정 연산, 메모리 접근에 특화

#### (1) 범용 레지스터

* **EAX (Accumulator) → 연산 결과, 함수 리턴 값 저장**
* EBX (Base) → 특정 주소 저장, 주소 계산에 사용
* ECX (Counter) → 루프 반복 횟수, 시프트 비트 수 기억
* EDX (Data) → 일반 데이터 저장, 곱셉/나눗셈 보조

#### (2) 세그먼트 레지스터

* CS (Code Segment) → 실행할 코드가 있는 세그먼트
* DS (Data Segment) → 일반 데이터가 있는 세그먼트
* SS (Stack Segment) → 스택 영역 베이스 주소
* ES, FS, GS → 여분

#### (3) 포인터 레지스터

* **EBP (Base Pointer) → 함수 호출 시 스택 프레임의 기준점**
* **ESP (Stack Pointer) → 스택 최상단 top을 가리킴**
* **EIP (Instruction Pointer) → 명령 포인터, 다음에 실행할 명령어의 주소**

#### (4) 플래그 레지스터

* 상태 플래그 CF PF AF ZF OF
* 제어 플래그 IF DF
* 시스템 플래그 VM RF AC

#### (5) 인덱스 레지스터

* EDI
* ESI

#### 주요 레지스터

* 스택 포인터 ESP/RSP → 스택 최상단
* 베이스 포인터 EBP/RBP → 함수의 기준점
* 명령어 포인터 EIP/RIP → 지금 실행중인 명령어 위치
* 연산 결과용 EAX/RAX → 연산결과, 리턴값

## 3. 스택 프레임

#### 함수 호출 규약

함수 호출 시 인자 전달, 리턴 값 처리, 스택 정리 방식 정의

* caller와 callee 사이 약속
* 아키텍처마다 다름
* x86-32bit architecture cdecl calling convention

  * 인자를 오→왼으로 스택에 push : func(a, b) 이면 b, a순으로 넣음
  * 리턴 값은 EAX 레지스터에 저장
  * 인자는 호출자(caller)가 정리 (인자 넣은 쪽에서 인자 정리)

#### Prologue

함수 시작 시 스택 프레임 설정하고 → 함수 실행에 필요한 환경 구성

* 목적 : 새로운 스택 프레임 만들기

```
push ebp
mov edp, esp
sub esp, 0x10
```

1. 기존에 ebp에 저장된 **주소 백업** (함수 끝난 후 돌아갈 주소)
2. ebp를 esp로 이동 → ebp를 현재 스택프레임 기준점으로 변경 (ebp를 top으로 올림)
3. esp(top)을 밑으로 내림 (스택은 위(높은주소)→ 아래(낮은주소)로 진행) → **로컬 변수** 공간 확보

#### Epilogue

함수 종료 시 스택 프레임 정리 → 이전 실행 환경 복원

* 목적 : 스택 프레임 정리하기

```
leave
ret
```

1. (leave) mov esp, ebp → 로컬 변수 공간 제거
2. (leave) pop ebp → 저장해뒀던 이전 ebp로 ebp 복원
3. (ret) pop eip → 스택에서 리턴 주소를 꺼내 eip에 넣기
4. (ret) jmp eip → 리턴주소로 복귀 (caller로 점프)

```
#include <stdio.h>

int add(int a, int b) {
	int result;
	result = a+b;
	return result;
}

int main() {
	int x = 3;
	int y = 5;
	int sum;
	
	sum = add(x,y);
	printf("sum = %d\n", sum);
	
	return 0;
}
```

\- 프롤로그 후                                                   - 연산

| return addr       |        | return addr       |        | eax |

| saved ebp         |        | saved ebp         |        | 8   |

| ----------------- | ------ | ----------------- | ------ | --- |

#### mov edx, DWORD PTR \[ebp+0x8]

* DWORD Double Word, 4바이트
* PTR Pointer, 뒤의 주소가 가리키는 메모리를 참조함
* \[ebp+0x8] ebp에 8바이트를 더한 메모리의 주소
* EBP + 8의 위치를 계산함
* 해당 메모리 위치에 0x3을 저장함

→ 기존 stack pointer 변경하지 않고 특정 메모리 위치의 값을 직접 수정

#### push DWORD PTR \[ebp+0x8]

* \[ebp+0x8] 에 있는 4바이트 값을 읽음
* ESP를 4만큼 감소시킴
* 감소한 ESP가 가리키는 stack 위치에 읽어온 값을 저장

→ 기존 메모리 값을 stack에 복사해서 쌓는 것

#### push 0x3

* 숫자 3을 stack에 넣음

## 3. gdb로 메모리 보기

```
#확인하고 싶은 곳에 break 걸기
(gdb) b add           #방법1 : (gdb) b <함수명>
(gdb) b *0x08049196   #방법2 : (gdb) b *<명령줄 주소>
(gdb) b *add+26       #방법3 : (gdb) b *<함수명 + 명령줄 번호>

#브레이크 포인트 확인
(gdb) info b

#예상 출력
#Num  Type        Disp Enb Address      What
#1    breakpoint  keep y   0x080491a6   in add
#2    breakpoint  keep y   0x080491ac   in add

#잘못 설정한 것 지우기
(gdb) delete 1
```

* 함수에 진입해 멈춘 후 가능한 것

  * 레지스터 확인
  * 함수의 어셈블리 확인
  * ESP부터 메모리 n개를 16진수로 확인
  * 특정 Stack 영역 확인
  * 현재 Stack Frame 정보 확인

## 4. gdb 명령어

명령어 설명 사용예시

| run / r                    | 프로그램 실행                    | (gdb) run           |
| -------------------------- | -------------------------- | ------------------- |
| break / b \[함수명]           | 해당 함수명 시작점에 break point 설정 | (gdb) break main    |
| next / n                   | 다음 줄로 이동 (함수 내부 들어가지X)     | (gdb) next          |
| step / s                   | 다음 줄로 이동 (함수 내부로 들어감)      | (gdb) step          |
| continue / c               | 다음 break point까지 실행        | (gdb) continue      |
| print / p \[변수명]           | 변수 값 보기                    | (gdb) print x       |
| info registers             | 레지스터 전체 보기                 | (gdb) info register |
| disas / disassemble \[함수명] | 디스어셈블링, 어셈블리 보기            | (gdb) disas main    |
| x/\[범위]\[출력형식] \[함수명/주소]   | 메모리 상태 검사                  | (gdb) x/20x $esp    |
